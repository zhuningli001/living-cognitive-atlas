# P0.8 Test Execution Runbook

Use this runbook to execute the first 3-5 person Chrome Memory Mirror external test.

## Goal

Run one small cohort and decide the next product loop from evidence.

P0.8 is not a public launch. It is a controlled test of whether invited users can:

- install the packaged unpacked extension
- understand the local privacy boundary
- scan bookmarks
- inspect the compact side panel
- open the built-in report
- mark feedback
- approve or ignore one rule
- re-scan
- clear local extension data

## Materials

Generate the package:

```bash
npm run package-extension
```

Send testers:

- `dist/chrome-memory-mirror-v0.1.1-unpacked.zip`
- the short invitation from `docs/tester-invitation.md`
- the checklist from `docs/external-tester-checklist.md`
- a GitHub Issue link using the `Extension test feedback` template, or a form based on `docs/external-feedback-form-schema.md`

Keep internally:

- `docs/p0.8-cohort-tracker.csv`
- `docs/p0.8-feedback-log.csv`
- `docs/test-cohort-retrospective.md`

## Privacy boundary

Do not ask testers to send:

- exported bookmark snapshots
- private bookmark URLs
- personal folder names
- screenshots showing sensitive bookmarks
- Chrome profile email, account id, cookies, browsing history, or page content

Ask testers to describe issues without exposing private bookmark data.

## Execution schedule

### Day 0: Prepare

- Run `npm run package-extension`.
- Confirm the package builds and checksum file exists.
- Pick 3-5 testers.
- Fill tester ids in `docs/p0.8-cohort-tracker.csv`.
- Send the invitation and package.

### Day 1-3: Collect

- Record completion state in `docs/p0.8-feedback-log.csv`.
- Ask one follow-up only when a tester is blocked.
- Keep feedback focused on install, trust, profile quality, feedback, rule approval, and reset.

### Day 4: Summarize

Run:

```bash
npm run summarize-cohort
```

Then copy the output into `docs/test-cohort-retrospective.md`.

### Day 5: Decide

Use one decision:

- Keep: the loop works; continue to a broader cohort.
- Simplify: testers completed the loop but found it too heavy.
- Deepen: testers understood the loop and want richer profile quality.
- Fix P0: blockers prevent repeatable external testing.
- Remove: a feature created confusion without adding trust or value.

## P0.8 pass condition

P0.8 passes when at least 3 testers complete the loop with score `2`, or when the blockers are specific enough to define the next P0 fix.
